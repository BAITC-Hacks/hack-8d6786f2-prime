# Сәт — умный подбор подрядчиков

Проект команды «Чайка PRIME» для HackAlem AI, кейс #79-lite.

## Краткое описание

Сервис помогает организатору мероприятия в Казахстане выбрать подрядчика из готового каталога. Вместо длинного списка он получает до трёх карточек с объяснением соответствия запросу. Основная ценность — понятное обоснование выбора и честное объяснение отсутствия результатов.

## Что реализовано

- Подбор по городу, дате, типу мероприятия, категории и бюджету в тенге; язык и длительность опциональны.
- Строгая проверка занятости, формата, цены, языка и применимой длительности, включая площадки.
- До трёх карточек с именем, категориями, городом, ценой и объяснением на основе исходных данных.
- Три разных исхода: подобрали; категории в городе нет; кандидаты есть, но условия не проходят. Неполная выдача объясняется.
- Повторяемый порядок по стартовой цене, затем id.
- AI-выбор исходной цитаты и локальный fallback при отсутствии ключа, сбое или таймауте модели.
- Отдельные проверенные альтернативы при изменении даты, бюджета, языка или длительности.
- SQLite-каталог, единый запуск сайта и API, маркировка синтетических профилей и дополненных данных.

## Как работает решение

Пользователь заполняет пять обязательных полей и при необходимости язык и длительность. После нажатия «Подобрать подрядчиков» сервер фильтрует каталог, упорядочивает прошедших кандидатов и показывает первые три. В каждой карточке есть конкретная цитата, цена и проверенные условия. Если результатов меньше трёх или нет, интерфейс объясняет причину. Альтернативы содержат явные отличия от запроса; применение изменений требует нового поиска.

## Технологии

| Часть | Используемые технологии |
| --- | --- |
| Backend | Python 3.12, FastAPI, Uvicorn, Pydantic, HTTPX, python-dotenv |
| Хранение | SQLite из стандартной библиотеки Python; CSV как источник первого импорта |
| Frontend | React 19, TypeScript, Vite, Zod, Lucide React |
| AI | OpenAI Chat Completions API, модель по умолчанию gpt-4o-mini; альтернативно NVIDIA API с указанной в конфигурации моделью |
| Проверки | pytest, Vitest, Testing Library, Playwright, axe-core |
| Упаковка | pnpm и lock-файлы; PyInstaller для Windows EXE |

Точные закреплённые зависимости находятся в `backend/requirements-lock.txt` и `frontend/pnpm-lock.yaml`. AI-модель не определяет цену, календарь или состав тройки. Дообучение и эмбеддинги не используются.

## Архитектура проекта

`CSV → SQLite → строгие фильтры → порядок по цене/id → до трёх кандидатов → проверяемые объяснения → карточки`.

- `backend/catalog.py` и `storage.py` импортируют данные и читают согласованный SQL-снимок.
- `backend/recommender.py` применяет условия и формирует проверенные альтернативы.
- `backend/explainer.py` выбирает цитату через AI или fallback; `recommendations.py` собирает ответ.
- `backend/application.py` и `api.py` обслуживают три маршрута: health, options, recommend.
- `frontend/src/App.tsx`, `api.ts`, `contracts.ts` реализуют интерфейс, запросы и проверку контракта.
- `run.py`, `backend/launcher.py` и `runtime.py` запускают один процесс и отделяют настройки от ресурсов приложения.

[Подробная архитектура](docs/architecture.md) · [Контракт API](contracts/api.md).

## Установка и запуск

Нужны Python 3.12 и Node.js 22.12+. Windows, из корня:

```powershell
.\scripts\setup.ps1
.\.venv\Scripts\python.exe -X utf8 run.py
```

Один процесс открывает и обслуживает сайт на http://127.0.0.1:8765 вместе с API. Отдельный сервер SQL не нужен. `setup.ps1` устанавливает зависимости по lock-файлам и собирает frontend. Если Python не на PATH: `scripts/setup.ps1 -Python <путь-к-python.exe>`.

Linux/macOS, из корня:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements-lock.txt
cd frontend
npx --yes pnpm@11.19.0 install --frozen-lockfile
npx --yes pnpm@11.19.0 build
cd ..
.venv/bin/python run.py
```

Для отдельной чистой демонстрации: `python run.py --data-dir <новая-папка>`. Дополнительные параметры: `--no-browser`, `--port 8766`. Ctrl+C останавливает приложение. API-документация доступна по `/docs`.

Готовый Windows EXE собирается отдельно: [сборка и проверка ZIP](docs/distribution.md). GitHub «Download ZIP» скачивает исходники, для них нужны команды выше. Ссылка на готовый релиз в текущую поставку репозитория не включена.

Без ключа работает подбор с явно обозначенными базовыми объяснениями. Для живого AI заполните `OPENAI_API_KEY` в локальном `backend/.env` и перезапустите приложение. Launcher создаёт этот файл при первом запуске; шаблон — `backend/.env.example`. При `--data-dir` настройки находятся в указанной папке. Не публикуйте `.env`.

[Настройки backend](backend/README.md) · [Разработка frontend](frontend/README.md).

## Как проверить решение

База: Алматы → 14.11.2026 → корпоратив → Ведущий → 1 500 000 ₸ → русский → 6 ч.

| Проверка | Изменение от базы | Результат на исходных 66 профилях |
| --- | --- | --- |
| Плотная категория | Нет | Три карточки из четырёх: HK-44923, HK-29829, HK-27222 |
| Повтор | Повторить без изменений | Тот же порядок |
| Редкая категория | Флорист, свадьба, 300 000 ₸, 8 ч, язык не задан | HK-90001; второй профиль занят |
| Никто не подходит | Бюджет 600 000 ₸ | Точных карточек нет; причины и отдельные альтернативы |
| Меняется только дата | От предыдущего: 15.11.2026 | HK-88430, от 500 000 ₸ |
| Категории нет в городе | От базы: Астана, Декоратор | Отдельное состояние отсутствия категории |

[Сценарий защиты](docs/demo.md), [матрица требований](docs/requirements-audit.md), [известные ограничения](docs/known-issues.md).

После установки зависимостей, из корня:

```sh
python -m pytest backend/tests qa/test_recommendation_http.py -q
python qa/run_e2e.py
```

Из `frontend`: `pnpm test` и `pnpm build`. Все изменяющие состояние проверки используют временные базы; массовые тесты не вызывают платный API. На Windows браузерные проверки используют Edge, на Linux/macOS установите Chromium: `pnpm exec playwright install chromium` в frontend. Если системная папка pytest недоступна, добавьте `-p no:cacheprovider --basetemp <новая-тестовая-папка>`.

Для отдельной проверки живой модели: `python -m backend.check_llm`. Команда делает один настоящий запрос, не выводит ключи и успешна только в режиме llm. `ai_available` в health показывает наличие настроек; фактический режим запроса — `meta.explanation_mode`. Результат с кешем не измеряет скорость нового внешнего вызова.

## Данные и интеграции

Источник — предоставленный для хакатона `data/contractors.csv`: 66 профилей, 17 категорий, анонимизированные имена. В наборе 13 synthetic-профилей, 18 подготовленных цен и 8 подготовленных городов; все флаги сохраняются. Календарь охватывает 23.09–31.12.2026. Цена — «от» за мероприятие, `max_hours=null` означает неприменимость присутствия.

CSV импортируется в SQLite один раз. Последующие запуски читают сохранённый каталог и могут работать без исходного CSV. HTTP API доступен только для чтения каталога и подбора. Для проверки исходных 66 записей используйте новую папку `--data-dir`; существующая база при обновлении не удаляется.

Внешние интеграции: `https://api.openai.com/v1/chat/completions` либо `https://integrate.api.nvidia.com/v1/chat/completions`. Модель получает параметры запроса, факты выбранных кандидатов и фрагменты описаний. Сервер проверяет возвращённые id и индексы цитат и формирует факты сам. Таймаут по умолчанию — 6 секунд, максимум 8; успешный выбор цитат кешируется до 256 запросов с учётом версии каталога. При ошибке используется fallback.

## Ограничения

- Бронирование, заявки, уведомления, оплата, регистрация и административная панель отсутствуют. Сервис только рекомендует.
- Свободное поле пожеланий исключено: API принимает только параметры кейса. Семантический рейтинг качества подрядчиков не заявляется.
- Даты вне исходного календаря отклоняются. Итоговая стоимость и фактическое качество услуги не проверяются.
- Проверяемость цитаты не гарантирует её полезность. Остаются случаи общих и взаимозаменяемых объяснений fallback и обрывов длинных фраз. Они перечислены в [known-issues.md](docs/known-issues.md) и требуют отдельного исправления.
- Наличие ключа не гарантирует доступность провайдера. Работа без интернета поддерживается через fallback, после установки зависимостей или в готовом EXE.
- Автоматические проверки не заменяют ручной оценки объяснений, проверки на другом компьютере и нагрузочных измерений.

Подтверждённой ссылки на публичную deployed-версию в репозитории нет. Для демонстрации используется локальный сайт `http://127.0.0.1:8765`. Windows ZIP — отдельная локальная поставка, а не публичное развёртывание. Порядок сборки описан в [distribution.md](docs/distribution.md).
