# Умный подбор подрядчиков

Проект команды «Чайка PRIME» для HackAlem AI. Сервис подбирает до трёх event-подрядчиков по городу, дате, формату, бюджету, языку и длительности и объясняет выбор по исходным данным.

## Проверка организаторами

Для Windows предусмотрена готовая поставка `SatContractors-Windows.zip`: распакуйте весь архив и откройте `Start.exe`. Приложение запускает один локальный сервер и открывает сайт на http://127.0.0.1:8765. Python, Node.js и сервер БД пользователю готовой сборки не нужны. Этот архив собирается отдельно; кнопка GitHub «Download ZIP» скачивает исходники и не заменяет исполняемую поставку.

База и настройки готовой сборки находятся в `%LOCALAPPDATA%\SatContractors`, поэтому замена папки приложения не удаляет анкеты. При первом запуске создаётся `.env` с индивидуальным `ADMIN_API_TOKEN`; скопируйте его значение в панель `/#/admin`. Для настоящего ИИ добавьте свой `OPENAI_API_KEY` в этот локальный `.env` и перезапустите приложение. Без ключа доступен весь цикл поиска и модерации с явно обозначенными базовыми объяснениями. Ключей разработчиков и рабочих SQL-баз в архиве нет.

Проверочный сценарий: Алматы → 14.11.2026 → корпоратив → Ведущий → 1 500 000 ₸ → русский → 6 ч. Результат: три карточки из четырёх подходящих профилей. При бюджете 600 000 ₸ — отдельные альтернативы. Новая анкета через «Подрядчикам» появляется в подборе после одобрения через «Администратору».

## Простой запуск из исходников

Нужны Python 3.12 и Node.js 22.12+. На Windows из корня репозитория один раз выполните:

```powershell
.\scripts\setup.ps1
```

Скрипт создаёт локальное `.venv`, устанавливает зависимости по lock-файлам и собирает интерфейс. Затем каждый запуск — одна команда:

```powershell
.\.venv\Scripts\python.exe run.py
```

Один процесс отдаёт сайт и API на http://127.0.0.1:8765. В исходниках настройки остаются в `backend/.env`, база — в `data/catalog.sqlite3`. При отсутствии `.env` launcher создаёт его с пустым ключом ИИ и случайным кодом администратора. Существующий файл никогда не перезаписывается. Vite нужен только для разработки или сборки, отдельный процесс frontend при таком запуске не требуется.

Параметры: `--no-browser`, `--port 8766`, `--data-dir C:\Sat-Test`. Последний создаёт независимые настройки и SQL-каталог для проверки. API-документация — `/docs`. Закрытие окна сервера или Ctrl+C останавливает приложение.

Сборка ZIP и проверка готового EXE: [инструкция поставки](docs/distribution.md). Устройство модулей: [архитектура](docs/architecture.md).

## Разработка: запуск бэкенда отдельно

Python 3.12. Из корня репозитория:

```sh
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-lock.txt
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

macOS/Linux:

```sh
.venv/bin/python -m pip install -r backend/requirements-lock.txt
.venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

После установки зависимостей сервер запускается одной командой. Документация запросов: http://127.0.0.1:8000/docs. Для разработки фронтенда: Vite на порту 5173, proxy `/api` на `http://127.0.0.1:8000`.

Ключ не требуется для проверки фильтров: в его отсутствие сервер возвращает фактические объяснения с `explanation_mode=fallback`. Для демонстрации ИИ скопируйте `backend/.env.example` в `backend/.env`, заполните доступный ключ и модель и перезапустите сервер. `ai_available` означает наличие настроек, а не результат проверки доступности внешнего API. Настоящий успешный вызов отражается в `explanation_mode=llm`.

Один живой запрос для диагностики модели: `python -m backend.check_llm`. Команда выводит результат без ключей и завершится успешно только при `explanation_mode=llm`.

## Запуск сайта

Оставьте backend работающим и откройте второй терминал. Нужны Node.js 22.12+ и pnpm 11.19.0:

```sh
cd frontend
npx pnpm@11.19.0 install --frozen-lockfile
npx pnpm@11.19.0 dev
```

Откройте http://127.0.0.1:5173. Сайт загружает параметры из каталога и отправляет запросы к backend через `/api`. Для проверки подбора: Алматы, 14.11.2026, корпоратив, ведущий, бюджет 1 500 000 ₸, русский, 6 часов. Должны появиться три карточки из четырёх подходящих профилей.

Дизайн, команды сборки и браузерные проверки: [frontend/README.md](frontend/README.md). В обычном запуске используются настоящие данные API; демонстрационные фикстуры включаются только отдельной командой `dev:mock`.

## SQL-каталог и новые подрядчики

Backend автоматически создаёт SQLite-базу `data/catalog.sqlite3` и один раз импортирует в неё 66 исходных профилей. После этого поиск и административная панель читают SQL. Одобрение, отклонение и удаление сохраняются между перезапусками; CSV не перезаписывает изменения. Другой файл базы можно задать через `DATABASE_PATH` в `backend/.env` (рекомендуется абсолютный путь). Файлы базы и локальные ключи исключены из Git. SQLite не требует отдельного сервера; схема использует таблицы профилей, категорий, форматов, языков, занятых дат, справочника и журнала действий.

На сайте есть публичная анкета подрядчика. После отправки она получает статус «На проверке» и не участвует в подборе до одобрения. В админ-панели доступны все анкеты, фильтры статуса, счётчики, просмотр, добавление, одобрение, отклонение с причиной и подтверждаемое удаление. Пароли подрядчиков не собираются. Контактный email виден только авторизованному администратору; в рекомендациях его нет.

Для административного доступа добавьте `ADMIN_API_TOKEN` в `backend/.env` и перезапустите backend. Используйте случайный код не короче 32 символов. Сгенерировать его локально можно командой Python:

```sh
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Введите этот код в поле доступа админ-панели. Он хранится только в памяти текущей страницы и сбрасывается при выходе или обновлении. Не публикуйте код и не добавляйте его в `.env.example`. Без серверного кода административные операции недоступны. Тесты используют свои временные БД и свои тестовые коды.

В демонстрационных анкетах включайте «Вымышленная тестовая анкета»: пометка `synthetic` останется видна в подборе. Справочники и окно календаря пока соответствуют исходному кейсу; анкеты за пределами этого окна отклоняются. Это подача анкеты без личного кабинета и самостоятельного редактирования подрядчиком.

## API

- `GET /api/health` — готовность и версия каталога.
- `GET /api/options` — справочники формы, календарь и количество профилей.
- `POST /api/recommend` — подбор, объяснения, причины исключения и проверенные предложения изменить дату.
- `POST /api/applications` — публичная подача анкеты на модерацию.
- `GET/POST /api/admin/profiles` — авторизованные просмотр и добавление.
- `POST /api/admin/profiles/{id}/moderate` и `DELETE /api/admin/profiles/{id}` — модерация и удаление с проверкой ревизии.

Контракт: [contracts/api-v1.md](contracts/api-v1.md). Реальная схема: `/openapi.json`.

Новые поля и административные операции: [contracts/platform-v2.md](contracts/platform-v2.md). Невалидные данные возвращают 422, отсутствие доступа — 401/503, повторная анкета или устаревшая ревизия — 409. Проверки выполняются в браузере и повторно на сервере. SQL-запросы параметризованы, удаление анкет и связанных записей атомарно.

Пример запроса:

```json
{"city":"Алматы","date":"2026-11-14","event_type":"корпоратив","category":"Ведущий","budget_kzt":1500000,"duration_hours":6,"language":"русский","preferences":""}
```

## Как работает подбор

1. SQL-база инициализируется из `data/contractors.csv`: 66 профилей, 17 категорий. Каждый запрос получает согласованный снимок одобренных SQL-записей. Версия данных — SHA256 содержимого этого снимка; изменение опубликованного каталога меняет версию и ключ кеша объяснений.
2. Строго проверяются город, категория, календарь, формат мероприятия, стартовая цена, выбранный язык и применимая длительность. Условия автоматически не ослабляются.
3. Кандидаты сортируются по числу точных совпадений значимых слов пожеланий с описанием, затем по стартовой цене, затем по id. Без пожеланий порядок определяется ценой и id. Это простая воспроизводимая эвристика, не рейтинг качества; синонимы и морфологические формы автоматически не распознаются.
4. Возвращаются первые три. Модель не может изменить их состав, порядок, цену или календарь.
5. ИИ выбирает наиболее полезный исходный фрагмент для каждого кандидата и аспект объяснения. Сервер проверяет id и индекс фрагмента, добавляет проверенные числовые факты и публикует `evidence`. Свободные неподтверждённые утверждения модели не отображаются.
6. При недоступности модели используется детерминированный выбор фрагмента; это явно отмечено `fallback`. Один внешний запрос обслуживает сразу все карточки, общий таймаут по умолчанию 6 секунд. Успешный выбор фрагментов кешируется в памяти на 256 запросов; порядок подбора от кеша не зависит.

`no_category` означает отсутствие категории в выбранном городе; `no_match` — наличие категории, но отсутствие кандидатов, прошедших все условия. Счётчики причин исключения могут пересекаться и не должны суммироваться как число уникальных профилей. При `no_match` сервер может предложить ближайшую подходящую дату в следующие 14 дней, повторно проверив все остальные ограничения.

Для одного-двух результатов `summary` отдельно объясняет, мало ли профилей в самом каталоге или сколько исключено конкретными условиями. Даты принимаются только в форме YYYY-MM-DD; длительность — числом, а не логическим значением или строкой.

Если точных совпадений нет, отдельный блок показывает до трёх альтернатив. Это не подходящие исходному запросу карточки: для каждой явно перечислены необходимые изменения даты, бюджета, языка или длительности. Город, категория и формат сохраняются. Дата проверяется по всему известному календарю: ближайшая свободная, при равном расстоянии — более поздняя. Сначала меньше изменённых условий, затем меньше нормированное отклонение (дни/7 + превышение бюджета/бюджет + 1 при смене языка + недостающая доля длительности), затем цена и id. Это прозрачная эвристика, а не модель вероятности качества. Применение условий требует отдельного нового поиска; занятый на исходную дату человек не считается свободным. Если ни один профиль не подходит даже с этими изменениями, альтернатив нет.

## Данные и ограничения

Данные предоставлены пользователем для хакатона. Имена анонимизированы; 13 профилей помечены `synthetic`, 18 цен — `price_imputed`, 8 городов — `city_imputed`. Все пометки сохраняются в API. Один профиль может иметь несколько категорий. Полные описания берутся из CSV, а не из сокращённого HTML-превью.

Эти количества относятся к первоначальному импорту. В дальнейшем одобренные анкеты добавляются в SQL-каталог, а удалённые исключаются. До подтверждения модератором описание новой анкеты — заявление её автора, а не проверенный опыт или рейтинг.

Календарь известен только с 23.09.2026 по 31.12.2026; остальные даты отклоняются. `max_hours=null` означает неприменимость ограничения присутствия. В новых анкетах это допускается только для флориста, декоратора, подарков и сувениров и их сочетаний; наличие любой другой категории требует числовой длительности. Цена — «от» за мероприятие, окончательная стоимость не известна. Нет бронирования, оплаты, уведомлений и внешнего обогащения каталога. Текст описаний отражает заявления профилей, не независимую проверку качества.

## Проверка

```sh
python -m pytest backend/tests -q
```

Используйте Python из созданного `.venv`. Тесты проверяют реальные сценарии CSV, границы бюджета и длительности, календарь площадок, пустые результаты, стабильность порядка после пересоздания сервера и резервный режим при ошибках модели. Вызовы провайдера в тестах имитируются; ключи и платные вызовы для тестов не требуются.

Проверочные сценарии: [backend/README.md](backend/README.md).

Проверка frontend из папки `frontend`: `npx pnpm@11.19.0 test` и `npx pnpm@11.19.0 build`. Команда `npx pnpm@11.19.0 test:ui` проверяет интерфейс в браузере; для четырёх дополнительных сценариев с настоящим backend следуйте [инструкции интеграционных тестов](frontend/README.md#проверки-в-браузере).

Независимая проверка SQL, HTTP-валидации, прав и жизненного цикла анкет: `python -m pytest qa/test_platform_http.py -q`. Сквозная проверка новых страниц в изолированной БД: `python qa/run_platform_e2e.py`. [Строгий аудит по исходному ТЗ и расширениям](docs/requirements-audit.md).
