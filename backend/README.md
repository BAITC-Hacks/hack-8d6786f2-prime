# Бэкенд подбора подрядчиков

Запуск из корня репозитория: `python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000` после установки `backend/requirements-lock.txt` в виртуальное окружение.

## Настройки

Скопируйте `.env.example` в `backend/.env`, вставьте ключ локально и не добавляйте файл в Git.

| Переменная | Назначение |
| --- | --- |
| LLM_PROVIDER | openai или nvidia; по умолчанию openai |
| OPENAI_API_KEY | Ключ OpenAI |
| OPENAI_MODEL | Модель OpenAI; по умолчанию gpt-4o-mini, доступность зависит от аккаунта |
| NVIDIA_API_KEY | Ключ NVIDIA |
| NVIDIA_MODEL | Доступная текстовая instruct/chat-модель NVIDIA, указывается явно |
| LLM_TIMEOUT_SECONDS | Общий таймаут запроса; по умолчанию 6, максимум 8 секунд |
| CONTRACTORS_CSV | Необязательный путь к исходному CSV |

Поддержаны запросы к OpenAI Chat Completions и NVIDIA NIM Chat Completions. OpenAI получает JSON Schema; NVIDIA — инструкцию вернуть JSON. Некорректный JSON, неизвестные id, отсутствующие фрагменты, ошибки HTTP и таймауты ведут к явно обозначенному резервному режиму. Поддержка API в коде не доказывает доступность конкретной модели или качество реального ответа; проверьте на выбранном ключе.

Для одной живой проверки после настройки выполните из корня:

```sh
python -m backend.check_llm
```

Команда делает один запрос к настроенному провайдеру и печатает режим, длительность и объяснения. Код завершения 0 означает успешный LLM-ответ, 1 — переход в fallback, 2 — отсутствие ключа/модели. Реальный вызов может расходовать API-баланс. Ключи и тела ошибок провайдера не выводятся; в журнал попадает только HTTP-статус либо тип сбоя. `401` у прямого OpenAI означает проблему авторизации: проверьте ключ и то, что он предназначен именно для api.openai.com, а не для отдельного сервиса организаторов. После изменения backend/.env перезапустите сервер. Никогда не заполняйте отслеживаемый Git файл .env.example действующим ключом.

Официальные источники: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [NVIDIA LLM APIs](https://docs.api.nvidia.com/nim/re/reference/llm-apis).

Идентификаторы используются только в тестовых ожиданиях. В алгоритме нет списков «правильных» подрядчиков.

## Структура

- `catalog.py`: чтение CSV, валидация и справочники.
- `models.py`: модели входа и выхода.
- `recommender.py`: фильтры, стабильный порядок и проверенные альтернативные даты.
- `explainer.py`: выбор подтверждающего фрагмента через LLM, таймаут и резервный режим.
- `app.py`: HTTP API и локальные CORS-настройки.
- `tests/`: автоматические проверки без внешних платных запросов.

Описание и пожелания передаются модели как недоверенные данные. Модель возвращает только ссылки на предоставленные фрагменты и допустимый тип акцента. Фактический текст цитаты, цена, язык, длительность и дата формируются сервером. Ключи и ответы провайдера не логируются.

В резервном режиме фрагмент выбирается по пожеланиям, тематическим основам названия мероприятия и конкретным особенностям услуги. Приветствия уступают содержательным фрагментам. Эта эвристика выбора цитаты не меняет опубликованный порядок карточек.

## SQL и жизненный цикл анкет

`storage.py` хранит профили и многозначные связи в SQLite. Файл по умолчанию `data/catalog.sqlite3`; `DATABASE_PATH` позволяет выбрать другой. CSV импортируется один раз при создании БД. `PRAGMA user_version=1` обозначает версию схемы, связи защищены foreign keys с каскадным удалением, изменения выполняются транзакционно. Используются WAL и отдельное SQL-соединение на операцию. Каталог справочников сохраняется даже после удаления всех анкет.

Поиск берёт только `approved`. Анкета через `/api/applications` получает `pending`; решение модератора и удаление сразу отражаются в следующих запросах и версии снимка. Если каталог изменился, пока выполнялся LLM-запрос, сервер повторно фильтрует свежий снимок и формирует проверенные резервные объяснения. Удалённый во время такого вызова профиль не возвращается из старого ответа модели.

`profiles.py` содержит модели записи: ограничения размеров, строгие числовые типы, уникальные списки и даты, проверку календаря и email. Допустимые города, категории, форматы и языки дополнительно проверяются по SQL-справочнику. Неизвестные поля, в том числе попытка задать status/id/password, отклоняются. HTTP-body ограничен 64 KiB; ошибки не отражают входные значения и секреты.

Админ-API требует `ADMIN_API_TOKEN` не короче 32 символов. Код не хранится в БД и не возвращается клиенту; используется сравнение с постоянным временем. Контакты входят только в административную модель ответа. Общий код доступа подходит текущей демонстрации; учетные записи сотрудников, персональные роли и личный кабинет подрядчика не реализованы.

Модерация и удаление требуют `expected_revision`. Конкурентная операция с устаревшей ревизией возвращает 409. Идентичная повторная анкета определяется SHA256 нормализованных полей. Журнал `audit_log` хранит идентификатор, действие и время, без текста анкеты и ключей. Удаление физическое; приложение не предлагает восстановление из журнала. Для резервного копирования используйте SQLite backup API либо копирование файла после остановки backend, а не копирование одного активного WAL-файла.

Точный контракт: [platform-v2.md](../contracts/platform-v2.md). Пустая строгая выдача может содержать до трех отдельных `alternatives`, которые подходят только после перечисленных изменений. Город, категория и формат никогда не меняются; ближайшая свободная дата ищется в полном известном календаре. Все альтернативы повторно проходят тот же строгий фильтр с предложенными параметрами, их объяснения строятся из данных без дополнительных платных вызовов.
