# Расширение API: SQL-каталог, анкеты, модерация и альтернативы

Рабочий контракт для интеграции. Исходный `/api/recommend` сохраняет строгие фильтры и статусы API v1. Все endpoint начинаются с `/api`. Пользовательские строки — текст, не HTML. HTTP 422: стандартный FastAPI `detail`; HTTP 401/403/409/503: `detail` — безопасная строка на русском.

## Альтернативы

В ответе `POST /api/recommend` добавляется `alternatives: []` (необязательное для старых ответов). Только для `no_match`, не более трёх вариантов, исходные `cards=[]` и `eligible_count=0` сохраняются.

Каждый вариант:

```json
{
  "card": {"...": "все поля Card из v1; available_on — реально свободная предложенная дата"},
  "changes": {"date": "2026-11-15", "budget_kzt": 700000},
  "differences": [
    {"field":"date","requested":"14.11.2026","proposed":"15.11.2026","reason":"На исходную дату подрядчик занят"}
  ],
  "explanation_mode": "fallback"
}
```

`changes` содержит только действительно изменяемые `date`, `budget_kzt`, `language`, `duration_hours`. Город, категория и формат мероприятия не меняются. Все различия перечисляются. Кнопка предлагает применить параметры к форме и требует отдельного повторного поиска. Не выдавать вариант за совпадение исходному запросу, не показывать исходную занятую дату как свободную. Подбор альтернатив основан на SQL-каталоге без дополнительного LLM-вызова.

## Анкета

`POST /api/applications`, без авторизации. Payload:

```json
{
  "name":"Название или имя подрядчика",
  "city":"Алматы",
  "categories":["Ведущий"],
  "event_formats":["корпоратив"],
  "languages":["русский"],
  "price_from_kzt":250000,
  "max_hours":6,
  "busy_dates":["2026-11-14"],
  "description":"Конкретное описание услуг, стиля работы и особенностей программы.",
  "contact_email":"contractor@example.com",
  "synthetic":false
}
```

Валидация: `name` 2–120 символов; описание 30–3000; цена — целое число 1–1 000 000 000; `max_hours` — число >0 и <=24; email до 254 символов и валидный базовый формат. Строки обрезаются по краям. Списки категорий/форматов/языков непустые, без дублей, строго из `/api/options`; даты уникальные YYYY-MM-DD в календаре API, максимум 100. Поля id/status/source/price_imputed/city_imputed/пароли не принимаются. `synthetic` — явная пометка вымышленной тестовой анкеты, по умолчанию false. Контакты не попадают в публичный подбор.

Правило длительности действует одинаково для публичной и административной формы. `max_hours=null` или отсутствие поля допустимы, только если **все** выбранные категории входят в `Флорист`, `Декоратор`, `Подарки и сувениры`. Это означает неприменимость присутствия. Если есть любая другая категория, включая смешанный выбор `Ведущий` + `Декоратор`, требуется число. Ошибка HTTP 422 относится к `detail[].loc=["body","max_hours"]`. Исходные данные CSV при импорте сохраняются без изменения.

201: `{"id":"USR-…","status":"pending","message":"Анкета отправлена на проверку. После одобрения она появится в подборе."}`. Идентичная повторная анкета — 409. Незавершённая/отклонённая анкета в каталоге не видна.

## Администратор

Все `/api/admin/*` требуют `Authorization: Bearer <ADMIN_API_TOKEN>`. Токен вводится в парольное поле интерфейса и хранится только в памяти, очищается при выходе. Никаких localStorage, URL или печати токена. При отсутствии серверной настройки — 503, неверный/отсутствующий токен — 401. Паролей подрядчиков в продукте нет. Данные токена и настройки провайдера никогда не возвращаются.

`GET /api/admin/profiles?status=all&limit=50&offset=0` — status: all/pending/approved/rejected; limit 1–100, offset >=0. Ответ:

```json
{
  "items": [],
  "total": 66,
  "limit": 50,
  "offset": 0,
  "counts": {"pending":0,"approved":66,"rejected":0},
  "storage": "sqlite"
}
```

Элемент `items`: все поля анкеты плюс `id`, `status`, `source` (dataset/application/admin), `revision` (>=1), `created_at`, `updated_at` (UTC ISO), `moderation_note`, `price_imputed`, `city_imputed`. У исходных CSV-профилей contact_email=null. `max_hours` и исходные пометки сохраняются. В списке доступны все анкеты, включая исходные 66. Нужны фильтр, счётчики, просмотр полных данных и пагинация.

`POST /api/admin/profiles` — тот же payload, что публичная анкета; сразу создаёт approved-профиль. Ответ 201 — полный элемент списка.

`POST /api/admin/profiles/{id}/moderate`:

```json
{"decision":"approved","expected_revision":1,"note":""}
```

decision approved/rejected, note до 500 символов (для rejected обязательна причина >=3). Статус можно менять повторно; повторное применение того же статуса — 409. Ответ — обновлённый полный профиль. Ревизия увеличивается, устаревшая ревизия — 409. Одобрение сразу включает профиль в подбор, отклонение исключает.

Перед одобрением пользовательская/административная анкета повторно проверяется по текущей модели записи. Старая анкета с недопустимыми полями получает 409 с просьбой подать исправленную; её статус и revision не меняются. Отклонение или удаление такой анкеты остаются доступны. Это правило не переписывает исходные профили dataset.

`DELETE /api/admin/profiles/{id}?expected_revision=1` — 204, физически удаляет анкету и её связи в одной SQL-транзакции. До вызова интерфейс спрашивает подтверждение с именем анкеты. Несуществующий id — 404, устаревшая ревизия — 409. Удалённый профиль сразу исчезает из подбора. Журнал хранит только id/действие/время, без тела анкеты и секретов.

## Хранилище и проверки

SQLite, файл `DATABASE_PATH` либо `data/catalog.sqlite3`. CSV читается только при первом успешном импорте. Готовая БД запускается даже при недоступном CSV; повторный запуск не перезаписывает базу, не возвращает удалённые записи и не теряет модерацию. Если первый импорт не удался, после исправления пути/CSV можно повторить запуск с тем же файлом БД. Исходный CSV хранится в репозитории как воспроизводимый seed. Снимок каталога и его version отражают только одобренные записи; новая pending-анкета не меняет выдачу. Все SQL-параметры передаются через placeholders.

Тесты используют отдельную БД и тестовый токен. Не удалять или модифицировать реальные профили в пользовательском сервере для проверки. Для независимого E2E рекомендуется backend на 8001 и Vite на 5174 с `BACKEND_URL=http://127.0.0.1:8001`; штатные порты остаются 8000/5173.
