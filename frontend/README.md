# сәт — Умный подбор подрядчиков

Русский интерфейс на React + TypeScript + Vite: подбор, публичная анкета подрядчика и панель администратора. Подбор, ранжирование и объяснения приходят с API v1/v2. Фронтенд не вызывает модели и не содержит ключей провайдеров.

Ветка `feat/provider-admin-ui` создана от `feat/catalog-platform` на `8af13b1`. Итоговая интеграция проверена с обновлённым backend **`c6e15d2`** из той же общей ветки. Для совместного запуска используйте эту версию backend или более новую совместимую: в ней согласовано правило обязательной длительности. Файлы backend и контрактов в ветке фронтенда не менялись; их обновление и слияние выполняет капитан.

## Запуск

Нужны Node.js 22.12+ (проверено на 24.19) и pnpm 11.19.0. Если pnpm не установлен, вместо `pnpm` в командах можно использовать `npx pnpm@11.19.0`.

Из корня объединённого репозитория запустите бэкенд по его инструкции, затем в другом терминале фронтенд:

```sh
# Терминал 1, корень репозитория; зависимости backend уже установлены
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000

# Терминал 2
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Откройте [http://127.0.0.1:5173](http://127.0.0.1:5173). Vite перенаправляет `/api` на `http://127.0.0.1:8000`. Порт 5173 фиксирован: при конфликте приложение не переходит незаметно на другой порт.

Для доступа к административной панели на сервере должен быть задан `ADMIN_API_TOKEN` длиной не менее 32 символов. Его вводят на странице входа. Не задавайте его через переменные с префиксом `VITE_` и не добавляйте в исходники.

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm preview
```

`preview` тоже использует порт 5173 и прокси API: предварительно остановите `dev`. Для единого локального запуска после сборки выполните `python run.py` из корня: FastAPI отдаёт `dist/` и `/api` на одном порту 8765. Vite и дополнительный reverse proxy в этом режиме не нужны. Настройки публичного интернет-хостинга выполняются отдельно.

## Режим демонстрации

```sh
pnpm dev:mock
```

Этот режим явно помечен полосой «Демонстрация», использует только `src/mocks/fixtures.ts` и позволяет переключать три, два, один результат, обе пустые выдачи, fallback, ошибку сервиса и ошибку полей. Все профили вымышленные. Параметры заранее заполнены для проверки внешнего вида; примеры не рассчитывают подбор по изменённой форме. Анкета и вход администратора в деморежиме отключены: переход на эти страницы не отправляет данные в настоящий API. Альтернативы проверяются отдельно с реальным сервером и в компонентных тестах.

Обычный `pnpm dev` всегда обращается к API. Ошибка API никогда не включает фикстуры. Production-сборка не включает демонстрационный режим, даже если задан `VITE_MOCK_MODE=true`, поскольку он дополнительно ограничен `import.meta.env.DEV`.

## Проверки в браузере

```sh
pnpm test:ui
```

На Windows тесты используют установленный Microsoft Edge. На другой системе установите Chromium через `pnpm exec playwright install chromium`. Другой канал можно выбрать переменной `PLAYWRIGHT_CHANNEL`.

16 проверок интерфейса подставляют контролируемые ответы на уровне тестового браузера. Само приложение запускается в обычном режиме API. Проверяются состояния, доступность, отправляемый JSON, порядок и предел карточек, аннотации данных, ошибки и мобильные размеры. В обычном запуске пропускаются четыре теста настоящего подбора и пять тестов SQL-платформы. Браузерные тесты в `tests/` принадлежат агенту 3 и этой веткой не изменены.

Для полной проверки с работающим FastAPI на 8000:

```powershell
# PowerShell
$env:RUN_BACKEND_TESTS='1'
pnpm test:ui
```

```sh
# Bash
RUN_BACKEND_TESTS=1 pnpm test:ui
```

Если среда Windows не завершает дочерний сервер после тестов, сначала запустите `pnpm dev` в отдельном терминале. Тесты переиспользуют этот сервер. Для воспроизводимых проверок настоящего backend используйте исходный каталог из его ветки и отключённые ключи модели: интеграционные ожидания проверяют `fallback` без платных запросов.

## Маршруты и новые сценарии

| Раздел         | Маршрут    | Поведение                                                                                                       |
| -------------- | ---------- | --------------------------------------------------------------------------------------------------------------- |
| Подбор         | `/#/`      | Исходная форма и отдельные альтернативы при `no_match`                                                          |
| Подрядчикам    | `/#/apply` | Публичная анкета; результат — номер и статус «На проверке»                                                      |
| Администратору | `/#/admin` | Вход, все источники анкет, счётчики, фильтр, страницы по 12 записей, просмотр, модерация, добавление и удаление |

В анкете справочники и диапазон дат приходят из `/api/options`. Занятые даты можно добавлять календарём, удалять по одной или вводить списком. Неверные, повторяющиеся и выходящие за диапазон даты объясняются рядом с полем. Повторная отправка блокируется; ошибка не очищает форму. Контактный email виден только в административном ответе и не показывается в публичных карточках.

**Длительность:** число больше 0 и до 24 включительно обязательно, если среди категорий есть любая услуга кроме `Флорист`, `Декоратор`, `Подарки и сувениры`. Смешанный выбор с ведущим или фотографом тоже требует число. Пустое значение отправляется как `null` только для указанных трёх услуг и означает неприменимость присутствия. Подсказка и обязательность поля обновляются при смене категорий. Это одно правило для публичного и административного добавления; исходные профили каталога остаются читаемыми без изменения данных.

Административный токен хранится только в состоянии открытой страницы. Выход, переход в другой раздел и перезагрузка очищают сеанс; после входа поле с токеном исчезает. Ответы отменённых запросов не могут восстановить приватный список или прервать новый сеанс. После 401/403 требуется повторный вход. При 404/409 действия с устаревшей версией блокируются до обновления списка; автоматического повторения изменений нет. Старая анкета, которую новый API запрещает одобрять, получает отдельное объяснение; её можно отклонить или удалить. Ошибки 422 привязаны к полям, 503 объясняет недоступность, серверные тела ошибок произвольно не отображаются.

Удаление требует подтверждения с именем анкеты: начальный фокус на отмене, Tab остаётся в диалоге, Escape закрывает его до начала запроса. Добавленный администратором профиль сразу получает `approved`; публичный — только после решения модератора.

Альтернативы показывают предложенную дату, описание, цену, каждое отличие `requested → proposed` и причину. Их нет в числе точных совпадений. Кнопка применяет изменения к форме и требует отдельного поиска. Город, категория и формат события не меняются; обычная подсказка смены даты продолжает работать рядом с альтернативами. Старый ответ API без `alternatives` и пустой массив допустимы.

## Изолированная проверка платформы

Полный набор создаёт и удаляет тестовые анкеты. Запускайте его только на отдельной БД с исходным seed, не на рабочем каталоге. Фронтенд умеет использовать внешний адрес через `QA_FRONTEND_URL`; в этом случае Playwright не запускает и не переиспользует сервер на 5173.

Пример PowerShell; backend берётся из копии `feat/catalog-platform` на `c6e15d2` или совместимом обновлении. Зависимости backend установлены по его инструкции. Подставьте один и тот же отдельный тестовый токен в первый и третий терминалы.

```powershell
# Терминал 1: корень копии обновлённого backend
$env:DATABASE_PATH = Join-Path $env:TEMP ('sat-ui-qa-' + [guid]::NewGuid() + '.sqlite3')
$env:ADMIN_API_TOKEN = '<отдельный тестовый токен не короче 32 символов>'
$env:OPENAI_API_KEY = ''
$env:NVIDIA_API_KEY = ''
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8001

# Терминал 2: frontend этой ветки
$env:BACKEND_URL = 'http://127.0.0.1:8001'
pnpm dev --port 5174

# Терминал 3: frontend этой ветки
$env:QA_FRONTEND_URL = 'http://127.0.0.1:5174'
$env:QA_DATABASE_ISOLATED = '1'
$env:QA_ADMIN_TOKEN = '<тот же отдельный тестовый токен>'
$env:RUN_BACKEND_TESTS = '1'
pnpm test:ui
```

Ожидается 25 пройденных браузерных тестов: 16 с управляемыми ответами и 9 с настоящим API. Только сценарии платформы можно запустить через `pnpm exec playwright test --config ../qa/platform-playwright.config.cjs` с теми же переменными. Отдельно `pnpm test` запускает 59 unit/component-проверок из `src/`.

## Поведение по контракту

- Списки и диапазон дат загружаются из `GET /api/options`; примеры из ТЗ не зашиты в рабочий интерфейс.
- `POST /api/recommend` получает обязательные параметры, числовой `budget_kzt`, `duration_hours: null` и `language: null`, если они не заданы, а также `preferences: ""` без пожеланий.
- Валидация перед запросом, ошибки FastAPI 422 у конкретных полей, отдельные сообщения о сети, ошибке сервера, неверном ответе и таймауте 20 секунд.
- На время запроса повторная отправка отключена. Изменение формы отменяет запрос и очищает старые результаты. Номер запроса дополнительно защищает от запоздалого ответа даже при игнорировании отмены транспортом.
- Показываются первые три карточки в серверном порядке. `eligible_count` остаётся числом всех подходящих, а не длиной видимого списка. Один или два кандидата — нормальная выдача.
- `matched`, `no_category` и `no_match` отображаются отдельно вместе с серверным `summary`. Пустой `suggestions` допустим.
- Подсказка показывает, какие условия изменит. Нажатие обновляет поля и сообщает об изменении; новый запрос требует нажатия «Подобрать подрядчиков».
- `synthetic` виден в карточке. Для `price_imputed` / `city_imputed` есть заметная отметка и раскрываемое пояснение. `max_hours: null` не превращается в часы и поясняется как неприменимость длительности.
- Имена, descriptions и explanations отображаются как текст React, без вставки HTML. Неизвестные поля подсказок отбрасываются схемой ответа.
