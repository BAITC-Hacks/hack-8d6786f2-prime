# Приёмка рекомендаций

`python qa/evaluate_explanations.py` воспроизводит 28 фиксированных запросов из `evaluation-cases.json` на всех 17 категориях и проверяет версию каталога. По умолчанию внешних вызовов нет. `--live` сравнивает текущий провайдер на том же наборе (24 платных запроса при исправной модели). `qa/artifacts/evaluation.json` содержит дату, SHA, признак незакоммиченных изменений, среду, цитаты, сигналы качества, свежие и повторные времена. Сигналы конкретности, различимости и окончания фразы — эвристики; успех не заменяет просмотра содержания.

`python qa/load_recommendations.py --requests 100 --concurrency 100` измеряет реальные localhost HTTP-запросы отдельного процесса с отключённым AI. Отчёт — `qa/artifacts/load.json`; сетевая ошибка или неверный ответ завершают команду с ошибкой.

CI: `.github/workflows/acceptance.yml`, Python 3.12, Node 24, Ubuntu, Chromium; ключи отключены. Playwright использует `qa/artifacts/browser`, чтобы очистка браузерных артефактов не стирала оценку и нагрузку.

Из корня: `python -m pytest backend/tests qa -q`. HTTP-набор поднимает отдельные процессы на свободных портах, отключает ключи модели и использует временные SQL-базы. Проверяет обязательные сценарии, отсутствие удалённых API, честность альтернатив и сохранность каталога после перезапуска.

`test_explanation_quality.py` проверяет дефекты QA-Q01/Q02/Q03: различающий состав двух групп на сентябрьскую и декабрьскую даты, те же факты в альтернативных карточках, завершённый фрагмент о свадебном опыте и единственное число в summary. Все шесть проверок воспроизводимо падали на `146b974` и проходят после исправления; xfail и пропусков нет. Проверяется содержание услуги, а не только неравенство строк после смены имени. [Разбор исправления](../docs/explanation-quality.md).

Frontend: `pnpm test` и `pnpm build` из frontend. Полный браузерный набор из корня: `python qa/run_e2e.py`. Он поднимает отдельные backend и Vite, проверяет настоящие запросы, состояния интерфейса, альтернативы, доступность и мобильную ширину. На Windows используется Edge; на других ОС установите Chromium для Playwright.

При отказе доступа к системной папке pytest добавьте `-p no:cacheprovider --basetemp <новая-папка>`. Pytest очищает выбранную папку, поэтому она должна быть отдельной тестовой директорией.

Тестовые фикстуры допускаются только в тестах. Приложение не переключается на фикстуры при ошибке API. Скриншоты и трассы остаются в игнорируемых qa/artifacts и frontend/test-results.

Ручная приёмка объяснений и известные контрпримеры: [known-issues.md](../docs/known-issues.md). Записывайте commit, режим объяснений, запрос, ожидаемый/фактический результат и время. Не называйте fallback проверкой живой модели; не объявляйте одинаковые рекламные цитаты качественными только потому, что они присутствуют в CSV.
