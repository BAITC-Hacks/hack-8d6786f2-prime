# Независимая приемка

`python -m pytest qa/test_platform_http.py -q` запускает отдельные процессы backend на свободных портах с временными SQLite-базами. Тесты обнуляют ключи LLM и используют вымышленный токен администратора. Рабочий сервер и его данные не затрагиваются.

Проверяются исходные демонстрационные сценарии, анкеты и модерация, авторизация, отсутствие контактов и секретов в публичных ответах, границы и типы полей, конкурентная ревизия, сохранность SQL после реального перезапуска процесса, честность и повторяемость альтернатив.

Сохранность не выводится из содержимого Python-объектов: процесс останавливается, новый процесс открывает ту же временную базу. Альтернативы сверяются независимо с CSV и повторным HTTP-запросом с явно предложенными условиями.

Эти проверки не измеряют качество живого LLM, не проводят нагрузочный аудит и не означают готовность к публичному размещению. Условия и ограничения приемки фиксируются в `docs/requirements-audit.md`.

После установки зависимостей frontend браузерная проверка запускается из корня:

```text
python qa/run_platform_e2e.py
```

Запускаются отдельный временный backend и Vite на свободных портах; тестовый токен передается только этому окружению. Проверка не подключается к штатному серверу. На Windows используется установленный Microsoft Edge; на другой системе нужен Chromium для Playwright. `PLAYWRIGHT_CHANNEL` позволяет явно выбрать установленный канал браузера. Браузерные артефакты находятся в игнорируемом `qa/artifacts/`.

При ограничениях доступа к системному каталогу pytest используйте новый временный каталог внутри своего рабочего пространства через `--basetemp` и при необходимости `-p no:cacheprovider`. Указывайте только выделенную тестовую папку: pytest очищает выбранный basetemp перед запуском.
