# Приёмка рекомендаций

Из корня: `python -m pytest backend/tests qa/test_recommendation_http.py -q`. HTTP-набор поднимает отдельные процессы на свободных портах, отключает ключи модели и использует временные SQL-базы. Проверяет обязательные сценарии, отсутствие удалённых API, честность альтернатив и сохранность каталога после перезапуска.

Frontend: `pnpm test` и `pnpm build` из frontend. Полный браузерный набор из корня: `python qa/run_e2e.py`. Он поднимает отдельные backend и Vite, проверяет настоящие запросы, состояния интерфейса, альтернативы, доступность и мобильную ширину. На Windows используется Edge; на других ОС установите Chromium для Playwright.

При отказе доступа к системной папке pytest добавьте `-p no:cacheprovider --basetemp <новая-папка>`. Pytest очищает выбранную папку, поэтому она должна быть отдельной тестовой директорией.

Тестовые фикстуры допускаются только в тестах. Приложение не переключается на фикстуры при ошибке API. Скриншоты и трассы остаются в игнорируемых qa/artifacts и frontend/test-results.

Ручная приёмка объяснений и известные контрпримеры: [known-issues.md](../docs/known-issues.md). Записывайте commit, режим объяснений, запрос, ожидаемый/фактический результат и время. Не называйте fallback проверкой живой модели; не объявляйте одинаковые рекламные цитаты качественными только потому, что они присутствуют в CSV.

## Дополнительные проверки календаря и качества объяснений

Из корня проекта с установленными зависимостями:

```sh
python -m pytest qa/test_core_acceptance.py -q -p no:cacheprovider
```

Новый набор использует существующий HTTP-helper, отдельный локальный процесс и временную SQLite. Он отключает загрузку .env и ключи AI; каждый запрос выполняется заново, без сохранённых ответов. Приложение, данные и существующие тесты не меняются.

Девять проверок покрывают пары занятых/свободных декабрьских дат для людей и площадок, конец календарного окна, отсутствие ограничения при max_hours=null, различимость объяснений без имён и завершённость выбранной цитаты. Последняя проверка адресована вручную оценённому абзацу HK-42352 и не является универсальным анализатором текста.

Исходные версии b68da2d и 146b974 имеют одинаковый backend. На них обнаружены QA-Q01 (одинаковые объяснения на двух датах) и QA-Q02 (обрыв цитаты): **6 passed / 3 failed**. Падения означают открытые дефекты, не ошибки установки. Не используйте xfail и не ослабляйте assert ради зелёного результата; после исправлений нужен новый прогон и ручная оценка полезности объяснений.

Для сохранения запросов и ответов задайте QA_RESULTS_PATH; для указания проверенного SHA — QA_REVIEWED_COMMIT. Необязательный QA_SOURCE_ROOT позволяет проверять отдельный исходный снимок; по умолчанию используется корень текущего проекта. Результат без QA_REVIEWED_COMMIT не заявляет, какой SHA проверен.
