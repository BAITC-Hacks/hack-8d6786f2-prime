# Следующий этап улучшений

Очистка объёма не закрывает замечания аудита качества. Следующие случаи остаются открытыми до отдельного исправления и повторной проверки.

1. **Взаимозаменяемые объяснения fallback.** Алматы, 23.09.2026, свадьба, Лайв-бэнд, бюджет 10 000 000, язык и длительность null. HK-23752 и HK-83709 стоят по 1 150 000 и получают одну рекламную фразу с разными названиями групп. После удаления названий объяснения одинаковы. Нужно выбирать фактические различия состава/услуги общими правилами, не по id.
2. **Обрыв цитат.** Ограничение excerpts в 220 символов режет некоторые фразы посреди мысли. Пример HK-42352 для свадьбы заканчивается «чтобы этот». Исправление не должно выдумывать продолжение.
3. **Мелкие формулировки.** Summary может содержать «1 не проходят» и «всего 1 профилей». Надписи про «людей» не всегда уместны для залов и услуг.
4. **Представление альтернатив.** Два блока с изменением условий можно объединить. Нельзя смешивать их с точной выдачей или менять параметры автоматически.
5. **Передача.** Проверенная локальная сборка не равна опубликованному GitHub Release. Жюри нужна доступная поставка или воспроизводимая инструкция исходников.

Поле пожеланий удалено из текущего API и UI, поэтому понимание свободного текста не заявляется. Технические тесты на валидность цитат не заменяют ручную оценку полезности и различимости объяснений. Проверка скорости живой модели должна отдельно отмечать кеш, таймаут и фактический explanation_mode.
