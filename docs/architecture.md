# Архитектура подбора

Один FastAPI-процесс обслуживает собранный React-интерфейс и API. Изменяемые настройки и SQLite отделены от исходников и ресурсов EXE.

| Модуль | Ответственность |
| --- | --- |
| backend/runtime.py, launcher.py, run.py | Пути ресурсов и конфигурации, единый запуск |
| backend/application.py, api.py | Создание приложения, валидация HTTP, три маршрута |
| backend/catalog.py, storage.py | Чтение CSV, первоначальный SQL-импорт, согласованный снимок |
| backend/recommender.py | Строгие фильтры, порядок по цене/id, проверенные альтернативы |
| backend/recommendations.py | Последовательность подбора и формирования ответа |
| backend/evidence.py | Полные исходные фрагменты, признаки услуги, приоритет отличительных фактов |
| backend/explainer.py | Выбор цитаты моделью или fallback, проверка результата, доказательства |
| frontend/src/App.tsx, components/ | Страница, отдельные EventForm, RecommendationResults, ContractorCard, Alternatives, SelectionDetails |
| frontend/src/useRecommendation.ts, api.ts, contracts.ts | Запросы, отмена устаревших ответов, предыдущий результат, runtime-контракт |

CSV → SQLite → ограничения → первые три по цене/id → объяснения → карточки. Условия никогда не ослабляются внутри точной выдачи. Для пустой выдачи отдельно вычисляются альтернативы; каждое изменение явно перечислено и повторно проверено.

Исходные описания разделяются по предложениям, пунктам списка и заголовкам. Длинный текст не режется по количеству символов: выбирается целый фрагмент либо законченный факт о стаже. Короткий фрагмент предпочтительнее, когда он сохраняет полезные сведения.

Модель получает уже выбранных кандидатов и пронумерованные исходные фрагменты после отбора. Обращения «звоните/закажите» и общая реклама уступают конкретным сведениям об услуге. Состав, инструменты, оборудование, вместимость и другие признаки сравниваются с описаниями остальных выбранных карточек; имена сами по себе отличием не считаются. Те же правила действуют для fallback и отдельных альтернатив. При недостатке данных используются имеющиеся сведения без выдуманных преимуществ. Это эвристический отбор, не универсальный анализ смысла.

Модель возвращает id, индекс фрагмента и аспект объяснения. Сервер отклоняет неизвестные id, индексы и ссылки на фрагменты, исключённые из переданного модели набора. Числовые факты и доступность формируются сервером. Валидный JSON сам по себе не гарантирует правильность содержания — это также отмечено в [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs). При сбое используется fallback; один запрос к провайдеру обслуживает всю тройку, таймаут 6 с по умолчанию. Кеш до 256 успешных ответов учитывает версию каталога и запрос.

SQL-каталог доступен для чтения через API. При обновлении старые базы схемы 1 сохраняются; дополнительные старые таблицы и закрытые поля не публикуются. Приёмка использует новую отдельную базу из исходных 66 записей.

Снимок загружается один раз и разделяется read-only запросами. Записи — frozen dataclass, списки — tuple/frozenset. `Store.refresh()` под блокировкой собирает новый согласованный снимок и атомарно заменяет ссылку; выполняющийся запрос сохраняет свою версию. Обычное обновление базы применяется перезапуском после завершённой SQL-транзакции. Новый seed импортируется в отдельную папку данных, существующая база сохраняется.

После LLM сервер сравнивает признаки всей группы с fallback. Потеря конкретных признаков или различимости карточки восстанавливает базовый набор цитат. Аспект объяснения от AI сохраняется, восстановление отмечается `meta.ai.quality_repaired`. Если фактов недостаточно и в источнике, карточка сообщает ограниченность описания. Это защита по эвристикам, не гарантия понимания смысла.

HTTPX-клиент переиспользуется и закрывается lifespan приложения. Одинаковые выполняющиеся запросы объединяются, независимые ограничиваются семафором и ограниченной очередью. AI-таймаут включает очередь; после трёх сбоев действует пауза 30 секунд. По умолчанию: 30 вызовов/мин и 500/процесс. Кеш учитывает версию, провайдера, модель, запрос и id профилей. Отмена одного HTTP-запроса не ломает общий результат.

`assessments` раскрывает причины исключения каждого профиля и ранг прошедших. Интерфейс сравнивает ответы только при одинаковой версии данных и смене одной даты. Выход за границу тройки не выдаётся за занятость. Число занятых видно и при matched.

Источник контракта — Pydantic/OpenAPI; TypeScript-типы генерируются через openapi-typescript, Zod сохраняет runtime-проверки. CI проверяет актуальность схемы/типов и 28 настоящих HTTP-ответов. TypeScript закреплён на совместимой с генератором версии 5.9.3.

При росте данных: перенести окно календаря в метаданные, согласовывать обновления нескольких процессов, ввести общую квоту AI и измерить необходимость SQL-фильтрации. Миграция СУБД, векторный поиск и семантический рейтинг без подтверждённой потребности не добавлены.

Система не бронирует, не принимает заявки и не уведомляет подрядчиков. Слабые места качества объяснений перечислены в [known-issues.md](known-issues.md).
