# Архитектура подбора

Один FastAPI-процесс обслуживает собранный React-интерфейс и API. Изменяемые настройки и SQLite отделены от исходников и ресурсов EXE.

| Модуль | Ответственность |
| --- | --- |
| backend/runtime.py, launcher.py, run.py | Пути ресурсов и конфигурации, единый запуск |
| backend/application.py, api.py | Создание приложения, валидация HTTP, три маршрута |
| backend/catalog.py, storage.py | Чтение CSV, первоначальный SQL-импорт, согласованный снимок |
| backend/recommender.py | Строгие фильтры, порядок по цене/id, проверенные альтернативы |
| backend/recommendations.py | Последовательность подбора и формирования ответа |
| backend/explainer.py | Выбор цитаты моделью или fallback, проверка результата, доказательства |
| frontend/src/App.tsx, api.ts, contracts.ts | Форма и карточки, запросы, проверка JSON-контракта |

CSV → SQLite → ограничения → первые три по цене/id → объяснения → карточки. Условия никогда не ослабляются внутри точной выдачи. Для пустой выдачи отдельно вычисляются альтернативы; каждое изменение явно перечислено и повторно проверено.

Модель получает уже выбранных кандидатов и пронумерованные исходные фрагменты. Она возвращает id, индекс фрагмента и аспект объяснения. Сервер отклоняет неизвестные id и индексы. Числовые факты и доступность формируются сервером. При сбое используется fallback; один запрос к провайдеру обслуживает всю тройку, таймаут 6 с по умолчанию. Кеш до 256 успешных ответов учитывает версию каталога и запрос.

SQL-каталог доступен для чтения через API. При обновлении старые базы схемы 1 сохраняются; дополнительные старые таблицы и закрытые поля не публикуются. Приёмка использует новую отдельную базу из исходных 66 записей.

Система не бронирует, не принимает заявки и не уведомляет подрядчиков. Слабые места качества объяснений перечислены в [known-issues.md](known-issues.md).
