# Демонстрация на 3–5 минут

Запустите приложение с отдельной новой папкой `--data-dir`, чтобы использовать исходные 66 профилей. Проверьте health и доступный календарь. Если показываете живую модель, настройте ключ в локальном .env, перезапустите приложение и подтвердите реальный режим llm. Не показывайте ключ на экране. Без ключа прямо называйте объяснения базовыми.

База: Алматы / 14.11.2026 / корпоратив / Ведущий / 1 500 000 ₸ / русский / 6 ч.

| Шаг | Действие | Что проверить и объяснить |
| --- | --- | --- |
| 1 | Базовый запрос | Три из четырёх, HK-44923 → HK-29829 → HK-27222. Сравнить конкретные исходные факты; объяснить порядок по стартовой цене, затем id |
| 1а | Только дата → 15 ноября | HK-88430 → HK-44923 → HK-35215. В сравнении дат HK-29829 занят, HK-88430 освободился, HK-27222 всё ещё подходит, но ниже первых трёх |
| 2 | Повтор без изменений | Тот же порядок; модель не выбирает случайную тройку |
| 3 | Флорист, свадьба, 300 000 ₸, 8 ч, язык не задан | Один HK-90001; второй занят. Synthetic виден, null-длительность означает неприменимость присутствия |
| 4 | От базы: 600 000 ₸ | no_match; объяснённые причины, точных карточек нет. Альтернативы требуют изменения условий |
| 5 | От шага 4: только 15.11.2026 | HK-88430; дата изменила доступность |
| 6 | От базы: Астана, Декоратор | Категории в городе нет — это другой пустой исход |

По запросу жюри: Астана / Отель / корпоратив / 10 000 000 ₸ / без языка и длительности. На 14 ноября занят; на 15 ноября HK-90012 свободен. Площадки используют те же правила календаря.

Пайплайн: CSV → SQL → строгие фильтры → цена/id → до трёх карточек → проверяемое объяснение. При пустой выдаче альтернативы показываются отдельно. Цена указана «от», календарь учебный, бронирования нет.

Качество объяснений ещё требует улучшения: [известные случаи](known-issues.md). Успешный показ выбранных примеров не доказывает качество всех объяснений.
