# Проверка backend расширения SQL-каталога

Исторический отчёт этапа backend. Последующая интеграция закрыла указанное ниже устаревшее QA-ожидание; актуальный результат и проверки готового приложения находятся в [отчёте поставки](distribution-verification.md).

Дата: 23.09.2026. Ветка: `feat/catalog-platform`, до интеграции окончательных изменений участников UI и QA. Все изменения тестовых профилей выполнялись в отдельных временных SQL-базах.

| Проверка | Результат |
| --- | --- |
| `python -m pytest backend/tests -q` | 77 passed; 4,53 с |
| `python -m pytest qa/test_platform_http.py -q` | 72 passed, 1 failed; 6,83 с |
| `python -m backend.check_llm` с локальным ключом и временным DATABASE_PATH | OpenAI, llm, 3 карточки, 1226 мс на объяснения |

Backend-набор проверяет исходный подбор, ограничения API, обработку ошибок модели, удаление во время подготовки объяснений и новые регрессии:

- Публичная и административная подача требуют числовую длительность для ведущего, фотографа и смешанных категорий. Null и пропуск поля возвращают 422 на `body.max_hours`, не создавая профиль.
- Флорист, декоратор, подарки и сувениры, включая их сочетания, допускают отсутствие длительности; анкету можно одобрить.
- Старая некорректная анкета не проходит одобрение. Статус, revision и журнал не получают частичных изменений; отклонение доступно.
- Новый экземпляр приложения с готовой SQL-базой запускается без исходного CSV, сохраняет модерацию, контакты и удаления.
- Неудачный первый импорт можно повторить после исправления пути; уже инициализированная база игнорирует изменения импортного файла.

Единственный сбой независимого HTTP-набора: `test_application_boundaries_and_trimming` ожидает 201 при добавлении ведущего с max_hours=null. Обновлённый контракт требует 422. Задача участника 3 — сохранить позитивную проверку null на флористе и добавить отрицательные случаи услуг присутствия. Файл QA не изменялся backend-владельцем. Полностью зелёная независимая приёмка пока не заявляется.

На этой Windows-машине обычный pytest встретил отказ доступа к старому системному temp-каталогу. Приведённые результаты получены с `-p no:cacheprovider --basetemp <новая папка внутри рабочего каталога>`; каждому прогону выделялась отдельная ранее не существовавшая папка. Исходники и условия тестов не менялись для обхода этой ошибки окружения.

Живой LLM проверялся отдельно от массовых тестов: CSV сначала импортирован в временную SQLite-базу, затем объяснения получены через реальный OpenAI API. Замер относится к одному вызову объяснений, не к браузеру или нагрузочному тестированию. Ключи и SQL-файлы в репозиторий не добавляются.

Следующий этап: синхронизация валидации в обеих формах, исправление указанного QA-ожидания, совместная сборка и браузерная приёмка после коммитов участников.
