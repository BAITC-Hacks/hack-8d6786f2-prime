## Открытые дефекты и замечания для капитана

Приоритеты: P1 — мешает выполнению ключевого критерия ТЗ; P2 — существенное качество/риск; P3 — формулировки или удобство. Это QA-приоритизация, не оценка баллов жюри.

### QA-Q01 — P1 — взаимозаменяемые объяснения, OPEN

Request:

```json
{"city":"Алматы","date":"2026-09-23","event_type":"свадьба","category":"Лайв-бэнд","budget_kzt":10000000,"duration_hours":null,"language":null}
```

Второй независимый пример: тот же JSON с date=2026-12-25.

Expected: у HK-23752 и HK-83709 остаются разные существенные основания выбора после удаления имён людей и групп. Actual: обе карточки по 1 150 000; после замены Thunder Breath Band и Eva Sound на [ИМЯ] **полностью совпадает всё explanation**, а не только одна фраза. Оба автоматических теста различимости падают.

Совпадающий фрагмент: «Начиная от модных ивэнтов до масштабных свадеб, «[ИМЯ]» идеально впишется в любой формат мероприятия». Остальные факты в объяснении — та же цена, бюджет, формат и дата. Удаление только anon_name недостаточно: название коллектива внутри цитаты тоже является именем.

Ручная оценка: в исходных описаниях есть различающие сведения. У одного коллектива перечислены два вокалиста и вокалистка, отдельные духовые инструменты; у другого — четыре вокалиста, струнный квартет и перкуссионист. Значит, совпадение объяснений нельзя оправдать отсутствием различающих исходных данных. Это не требование выдумывать новые свойства, менять ranking или цены.

Критерий закрытия: обе даты проходят строгую регрессию и ручную оценку полезности; разные имена, знаки препинания или перестановка слов сами по себе исправлением не считаются.

### QA-Q02 — P2 — незавершённая цитата, OPEN

Request:

```json
{"city":"Алматы","date":"2026-09-23","event_type":"свадьба","category":"Ведущий","budget_kzt":10000000,"duration_hours":10,"language":"казахский"}
```

Expected: понятный завершённый фрагмент без придуманного продолжения. Actual: у HK-42352 выбран фрагмент длиной 216 символов; заканчивается «гостей и делаем все, чтобы этот». В CSV продолжение — «день запомнился всем на всю жизнь.». Принадлежность quote исходному description подтверждена, но читаемость нарушена. Тест границы фразы падает.

Критерий закрытия: выбрать другой законченный фрагмент либо сохранить завершённую исходную мысль; потом перепроверить смысл вручную. Новый тест — адресная регрессия этого абзаца, а не универсальный алгоритм анализа русской речи.

### QA-Q03 — P3 — согласование числительных, OPEN

## Установка, версии и ограничения

Ubuntu 26.04 LTS; Python 3.14.4; Node 22.22.1; pnpm 11.19.0; предыдущий браузерный прогон — Chromium 153.0.8010.12. SHA приложения указан в начале документа. Для 146b974 повторно использованы зависимости из неизменённых lock-файлов; новая сборка выполнена в отдельном архиве. ZIP 146b974 скачан через GitHub API и сравнён с ним: все 69 отслеживаемых файлов совпадают, приватных/генерируемых файлов нет.

Предыдущая установка выполнена на свежем архиве без существующих .venv/node_modules/dist/.env. Зависимости из lock-файлов установились, TypeScript/Vite build и запуск `run.py` прошли. Эти действия повторно не выполнялись. **ENV01:** README рекомендует Python 3.12; на машине он отсутствует, поэтому точную команду `python3.12 -m venv .venv` и эту версию runtime не считаем проверенными. Успех на 3.14 не выдаётся за проверку 3.12 или Windows.

Проверка живой модели требует отдельного согласованного доступа. В текущей работе ai_available=false; платные API и ключи не использовались. Сохранённый или имитированный ответ не учитывается как новый live LLM-вызов.
